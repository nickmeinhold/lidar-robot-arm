Pi ↔ Waveshare UART Wiring

Staleness note (added on import, 2026-11-14)

This page was written for a Pi 4 with USB as Plan A. The actual bench Pi is armbench, a Pi 3B+ whose USB is dead — Plan A does not apply there. Plan B's pins (GPIO-UART: pins 6/8/10) are correct on both boards. If anything elsewhere in this repo now contradicts this page, trust the repo over this note.

Arm bench hookup: Waveshare adapter → Raspberry Pi

Plan A (today): one USB cable, jumpers at B. Plan B (when Dupont wires arrive): GPIO-UART, jumpers at A. Servo power stays on the 7.4 V barrel supply in both plans.

Plan A — USB mode (today)

Plan B — GPIO-UART (when jumper wires arrive)

Pin table (same information, checklist form)

WireWaveshare adapterRaspberry Pi
TX TX (UART header)pin 8 — GPIO14 / TXD
RX RX (UART header)pin 10 — GPIO15 / RXD
GND GND (UART header)pin 6 — GND
5V / V+ 5V pin— not connected, nothing, never —

Pin 1 is the corner pin nearest the SD-card slot; even pins are the row along the board edge. Counting from pin 2: 2, 4, 6, 8, 10 — your three wires are three consecutive pins in that outer row.

Bench sequence

  1. Power off the 7.4 V servo supply while wiring. (The adapter is already free — nothing is plugged into the Mac; confirmed 2026-08-15.)
  2. Move both yellow jumper caps to position A — the pair of caps slides toward the far end of the board, away from the USB-C connector. (The "A"/"B" printed next to the two servo sockets is a different A/B — ignore that one.)
  3. Run the three wires per the table: TX→pin 8, RX→pin 10, GND→pin 6. Same name to same name — Waveshare's UART labels are host-referenced, so it's deliberately not crossed like old-school serial.
  4. Plug the 7.4 V barrel supply back in. Servos and adapter logic both feed from it.
  5. Tell Claude. The bus probe runs from the Pi — ping all six servo IDs, read voltages — before anything moves.

The one wire that must never exist

No power wire between the adapter and the Pi — not the adapter's 5V pin, not servo V+, nothing from the barrel-supply side. The Pi's GPIO is 3.3 V logic at milliamps; six STS3215s pull amps at 7.4 V. The only shared conductor is ground.

Looks wrong, isn't

  • The PWR LED stays dark. It's powered by USB-C logic power, which no longer exists in this setup. The board is fine — the truth instrument is a voltage-register read from the Pi, which Claude runs at bring-up.
  • No response on first try? Swap the TX and RX wires at the Pi end — the harmless first debug step if the not-crossed convention turns out crossed on this board revision.

Pi side is already configured and verified: /dev/serial0 → ttyAMA0 (PL011 via dtoverlay=disable-bt), 1,000,000 baud accepted, serial console freed. Config backups: /boot/firmware/*.bak-armbench.
